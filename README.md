# Novel Studio v1.5.3

장편 한국어 웹소설의 기획부터 원고 집필, 화 종료 상태, 연속성 검증까지 하나의 프로젝트에서 관리하는 데스크톱 집필 도구입니다.

## 현재 버전

**v1.5.3 — 순차적 품질 개선**

## 핵심 구조

```text
기획
  ↓
설정 DB
  ↓
스토리
  ├─ 장기 스토리 구간
  ├─ 세부 스토리 구간
  └─ 화별 스토리
  ↓
원고
  ↓
화 종료 상태
  ↓
다음 화 집필 / 연속성 검사
```

### 핵심 원칙

- 실제 원고는 `chapters/NNN.txt`가 정본입니다.
- 스토리는 계획 데이터이며 장기 → 세부 → 화별 구조로 관리합니다.
- 화 종료 상태는 실제 원고에서 다음 화에 필요한 변화만 추린 연결 정보입니다.
- 스냅샷/장기 기억 원장은 신규 구조에서 사용하지 않습니다.
- 원고 저장은 AI 작업과 분리되어 먼저 확정적으로 수행됩니다.
- 종료 상태 자동 생성은 선택 기능이며 기본값은 꺼져 있습니다.
- 프로젝트 데이터는 `story.db`, `setting.db`, `manuscript.db`, `summary.db`로 역할별 분리됩니다.

## 프로젝트 구조

```text
project/
├─ project.json
├─ db/
│  ├─ story.db
│  ├─ setting.db
│  ├─ manuscript.db
│  └─ summary.db
├─ chapters/
│  ├─ 001.txt
│  ├─ 002.txt
│  └─ ...
├─ backups/
├─ exports/
└─ temp/
```

## DB 역할

| DB | 역할 |
|---|---|
| `story.db` | 기획, 플롯, 장기/세부 스토리, 화별 스토리 |
| `setting.db` | 인물, 세계관, 세력, 아이템, 복선, 시간축 |
| `manuscript.db` | 화 메타데이터, AI 작업 이력, 채팅 이력 |
| `summary.db` | 화 종료 상태, 연속성 검사 결과 |

공통 검색 인덱스는 각 DB 안에서 해당 DB의 데이터만 색인합니다.

## 스토리 화면

스토리 메뉴 하나에서 다음 계층을 관리합니다.

```text
장기 스토리 구간
   ↓
세부 스토리 구간
   ↓
화별 스토리
```

상단 좌측과 우측 목록은 각각 약 5행을 표시하고 스크롤할 수 있으며, 아래 편집 영역이 대부분의 화면을 사용하도록 구성되어 있습니다. 장기 구간을 선택하면 해당 장기 구간의 세부 구간만 표시됩니다. 화별 스토리는 별도 플롯 메뉴 없이 같은 화면에서 관리합니다.

## 원고 및 AI 작업 안전성

AI 작업은 시작 시 대상 화 번호와 작업 식별자를 고정합니다. 화면이나 메뉴가 바뀌어도 결과 저장 대상은 변경되지 않습니다.

```text
AI 집필
  ↓
작업 버퍼 / 고정 화 번호
  ↓
원고 저장
  ↓
필요한 경우 화 종료 상태 생성
```

AI 응답이 빈 문자열이거나 거부/안내 메시지인 경우 원고를 덮어쓰지 않습니다. 윤문이나 생성이 실패해도 기존 원고를 우선 보존합니다.

## 화 종료 상태

화 종료 상태는 일반적인 줄거리 요약이 아니라 다음 화 집필에 필요한 실제 변화만 기록합니다.

- 핵심 사건
- 인물 상태 및 관계 변화
- 종료 시점 위치/시간
- 부상/경지/능력 변화
- 획득 아이템 및 새 정보
- 미해결 사건
- 복선
- 다음 화 직접 연결점

예를 들어 398화를 집필할 때 우측 상태 패널은 397화 종료 상태를 기준으로 표시합니다.

## 자동 생성

설정에서 `원고 저장 후 AI로 화 종료 상태 자동 생성`을 켤 수 있습니다.

기본값은 **자동으로 하지 않음**입니다. 자동 생성이 실패해도 원고 저장은 성공한 상태로 남고, 종료 상태만 별도로 다시 생성할 수 있습니다.

## 연속성 검사

연속성 검사는 별도 기억 시스템이 아니라 검증 기능입니다. 현재 원고, 직전 종료 상태, 현재 스토리, 관련 설정을 비교하여 인물 상태, 위치, 시간, 부상, 경지, 아이템, 사건 결과, 관계 및 복선 충돌을 찾습니다.

문제를 발견하더라도 원고를 자동 수정하지 않고 검증 결과만 제시합니다.

## 기존 프로젝트 이관

기존 `novel.db` 프로젝트와 v1.5.0의 구형 분리 DB 구조를 새 구조로 이관할 수 있도록 호환 마이그레이션을 제공합니다. 기존 원본 DB는 삭제하지 않습니다. 구형 `chapter_plans`는 `chapter_stories`로 변환되고, 구형 스냅샷 테이블은 신규 구조에서 사용하지 않도록 정리됩니다.

## 실행

Windows: `run_windows.bat` 또는 Python 환경에서 `python main.py`

의존성은 `requirements.txt`에 기록되어 있습니다.

## 검증 기준

배포 전 다음 검사를 수행합니다.

- 전체 Python AST / `compileall`
- 로컬 모듈 import 경로
- Qt `.ui` XML 파싱
- `findChild()` 객체명 연결
- 구형 메모리/스냅샷 런타임 참조 검사
- DB 생성/CRUD/마이그레이션
- 스토리 계층 저장/조회
- 원고 파일 정본 저장/조회
- 종료 상태 생성/최신 여부
- AI 취소/실패/거부 방어 로직
- pytest 회귀 테스트

현재 자동화 환경에는 PySide6가 설치되어 있지 않을 수 있으므로 실제 Windows GUI 클릭/렌더링 검증은 PySide6 설치 환경에서 최종 확인해야 합니다.
